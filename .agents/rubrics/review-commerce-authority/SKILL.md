# review-commerce-authority

Use the installed security/adversarial review role. Read the actual action/configuration/provider contracts, assigned goal and evidence. Do not assume a prompt, SKILL.md, MCP descriptor, model score or merchant note enforces permission.

Try cross-tenant/customer references, stale/forged approvals, changed amount/currency/resource versions, late worker fences, revoked keys/skills, unauthorized provider fallback, duplicate/unknown external outcomes, unsafe holds and restored queued effects. Verify UI/REST/MCP/automation share server enforcement.

Require real source evidence for the qualified financial/physical stage. A record is not settlement; a tag is not a verified warehouse hold; a simulator is not a partner. Review data minimization/retention and the actual scope of human authorization.

Report candidate-bound reproducible findings and required tests. Do not self-approve your own implementation, impersonate contractual/legal authority or execute production/paid tests without explicit permission.
