# M14-G05 — Prove controlled replacement and publish scoped compatibility

**Milestone:** M14 · **Type:** worker_goal · **Lane:** decision_models_and_skills · **Risk:** critical

**State:** not started · **Owner:** unassigned · **Execution:** local_then_separate_qualification

> Planning specification only. No application test, provider operation or feature completion is claimed.

## Outcome

Support rollback and model changes without losing case state, with a portability claim based on two actual implementations and a separate one-backend routing claim when that is all the evidence supports.

## Dependencies

[M14-G03](../M14/M14-G03.md); [M14-G04](../M14/M14-G04.md); [M13-G99](../M13/M13-G99.md)

Dependencies must be **accepted**, not merely assigned or implemented. Inspect current accepted evidence before starting.

## Bounded ownership

- Apply the predeclared comparison/qualification protocol to the second actual implementation when available and record outcomes against the same supported task.
- Reuse existing canary, publication, rollback, revocation, and compatibility records to switch only among qualified configurations.
- Retain original observations and case state across replacement; new inference creates a new observation and cannot silently alter existing approvals.
- Publish separately the implemented transport capabilities, qualified scoped routes, actually exercised backend pairs, pending self-hosted work, and known numerical/quality differences.

Additive specification from the separately retained roadmap. Concrete assignment and allowed paths require a prior maintainer record; only M13 is assigned by ADR-0042.

7. Run affected routing/provider/qualification checks during iteration; execute the predeclared qualification cohort at a model/schema/configuration release boundary instead of after every edit.
8. Before measuring qualification outcomes, freeze the use case, cohort/strata, baseline, success/error definitions, calibration procedure, held-out split, thresholds or threshold-selection rule, handling of uncertainty, and maximum tolerated wrong routing. No after-the-fact benchmark targets.
9. Activating scoped routing requires actual observations from at least one approved model/backend on the declared cohort and approval through the existing publication mechanism; a fixture-only backend remains shadow/review-only.
10. Claiming backend portability requires two actually exercised serving implementations completing the same declared task, including comparisons and configuration-specific qualification. Two synthetic transport fixtures are insufficient.
11. A self-hosted Clef qualification must prove the trained joint schema head and backbone were loaded, pin serving/model artifacts, record the effective context limit and confidence semantics, and report numerical differences.
12. Inherited production and formal release gates remain effective; case-routing qualification does not qualify refunds, visual evidence, autonomous case resolution, or external-agent egress control.
