1. Inspect the actual repository, installed workflow and accepted dependency evidence before writing code.
2. Resolve proposed module/test locations and bind the goal to existing commands; no invented executable commands or preclaimed application tests.
3. Use a dedicated worktree and isolated data/services; preserve the protected baseline and minimize sensitive evidence.
4. Bind a separate worker branch and concrete write paths to the newest M08 source checkpoint. This proposal changes neither that source nor its accepted-goal ledger.
5. Inspect and reuse packages/agent/mcp.mts, the current worker HTTP contract, packages/commerce/work-leases.mts, authorization.mts and kernel.mts. The checkpoint has explicit local opaque grants and bounded worker leases; it does not establish deployed OAuth or sender-bound remote qualification.
6. Treat milestone dependencies as integration and qualification dependencies. Local contract, fixture and implementation work may proceed under its normal assignment while formal prerequisite acceptance remains open; it must not report those prerequisite milestones as accepted.
7. Use signed synthetic issuer fixtures, independent local clients and isolated development storage. Select an actively maintained standards library after checking its documented support; do not implement cryptographic primitives or a new general authorization server.
8. Follow DEVELOPMENT.md and ADR-0032: inspect the affected-file plan, run a coherent focused selection once, and repeat only for a concrete failure or material correction. The default is at most 60 cases in four whole files within one 60-second deadline. Full applicable acceptance evidence belongs to the required integrated gate, not every goal.
9. Before enabling a real remote route, identify the actual issuer, client, HTTPS origin, proxy trust configuration, token confirmation mechanism, shared replay store and deployment profile. Confirm that the issuer supports the selected sender-constrained profile; fixture-issued tokens do not qualify a deployed issuer.
10. Observe the exact deployment with at least two verifier processes or replicas, restart and fail-closed replay-store behavior, revocation and one independently implemented client. Keep tokens, private keys and customer payloads out of retained evidence.
11. Obtain the existing scoped authorization for connected credentials and effects. A synthetic remote read/proposal exercise does not authorize production data access or financial execution.
12. Complete applicable existing target-stack, integration-readiness, independent security and formal acceptance obligations separately. Current SQLite diagnostic success cannot establish PostgreSQL, production availability or a fully accepted M07/M08 release.
