# M16-G05 — Define optional gateway policy and observed enforcement limits

**Milestone:** M16 · **Type:** worker_goal · **Lane:** security · **Risk:** critical

**State:** not started · **Owner:** unassigned · **Execution:** local_then_separate_qualification

> Planning specification only. No application test, provider operation or feature completion is claimed.

## Outcome

Make optional inference gateway use an explicit operator choice with inspectable privacy, routing, billing and enforcement settings, without making it a prerequisite for core runtime security.

## Dependencies

[M16-G01](../M16/M16-G01.md); [M16-G04](../M16/M16-G04.md); [M15-G99](../M15/M15-G99.md)

Dependencies must be **accepted**, not merely assigned or implemented. Inspect current accepted evidence before starting.

## Bounded ownership

- Coordinate with the M14 provider/decision contract. Own the trusted gateway policy profile and enforcement observations; do not duplicate the decision adapter or require gateway usage.
- Pin account/gateway/model-route identity, authorized provider destinations, credential references, billing mode, fallback behavior, budgets, payload/metadata logging, retention and cache behavior in trusted configuration.
- For the first optional Cloudflare profile, use bounded text and nonstreaming responses; prefer metadata-only gateway logging with cf-aig-collect-log-payload:false, disable sensitive response caching initially and prevent unapproved billing/provider fallback.
- Document the actual product boundary: DLP is text-scoped; cache hits may avoid rescanning; unsupported response types and some streaming paths have different enforcement behavior. Qualify the selected route instead of claiming universal guardrail coverage.
- Distinguish Workers AI ordinary inference data handling, optional stateful features, AI Gateway logs and the selected provider/BYOK contract. Do not apply Unified Billing's retention terms to BYOK.
- Use separate gateway instances where tenant policies cannot safely share gateway-wide settings. Prevent clients or prompts from overriding trusted policy headers, routes or data destinations.
- Allow three honest outcomes: disabled/not requested, locally configured with synthetic wire evidence, or live-qualified for one named route. Absence of a gateway does not fail M16's core isolation/graph result or the manual path.

Additive specification from the separately retained roadmap. Concrete assignment and allowed paths require a prior maintainer record; only M13 is assigned by ADR-0042.
