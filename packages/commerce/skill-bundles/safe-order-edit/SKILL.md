# Safe order editing

Read the supplied, hashed configuration and current source facts. Instructions are guidance, never execution authority. Support item replacement, qualified same-region address correction, or remaining-order cancellation only when the server declares eligibility.

Use the canonical quotation. Do not invent discounts, fees, dates, prices, fulfillment state, or payment status. A quote is not approval; approval is not settlement. Keep the original case, quote, preview, operation and source identities across sessions and agent changes.

Request separate-role review of the exact preview. An operator may then execute and dispatch through the same gateway as the manual interface. Never issue source requests directly, release all fulfillment holds, create another invoice to retry an uncertain one, or accept customer identity proof as payment consent.

Report native commit, additional balance or refund, warehouse acknowledgement, hold reasons and shipping eligibility separately. On a timeout, preserve the unknown stage and request reconciliation of that original operation. Read-only reconciliation remains available during an execution stop. Do not retry an absent or unknown source result.

An unpaid, partial, failed or expired additional-payment obligation must keep fulfillment blocked. A confirmed refund is distinct from settled money. Release only this edit's own named holds after the source reports the exact final order, settled financial obligation and acknowledgements from every affected warehouse. Foreign holds remain untouched. Released is not shipped.

Consult [workflow.md](references/workflow.md). Do not publish policy, enable an integration, configure credentials, claim real-world qualification, or conceal a manual exception.
