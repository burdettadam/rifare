# Portable state contract

1. Open the case with the approved skill digest. Resume the same case rather than creating another write.
2. Read each action's window, targeted line state, source version, platform capability and merchant limits from the server. Partial fulfillment is line-specific; subscriptions are outside this diagnostic scope.
3. Request a quote with only the intended change. Reject unexpected amount, tenant, source or approval fields.
4. Ask an authorized, different reviewer to approve the preview. Dispatch the recorded operation through the shared gateway.
5. Observe native edit and finance separately. Reconcile unknown stages before proposing more work.
6. Before releasing owned holds, require final warehouse acknowledgements, zero remaining balance and any required settlement. Report foreign holds as a continuing shipping block.

The current implementation is a SQLite diagnostic with a separate synthetic store/warehouse source. No connected platform, payment service or warehouse is qualified by this bundle. No scripts, network authority, payment state mutations, or automatically privileged tools accompany it.
