# M14 — Calibrated routing and backend replacement

Qualify one actually measured decision backend for a bounded routing task, retain review and manual operation, and add a separately evidenced backend-replacement path. Scoped routing does not require GPU or self-hosting expenditure; a portability claim additionally requires two actually exercised implementations.

## Required integrated demonstration

Classify and route an ordinary case through a named qualified configuration, review uncertainty, fence a late result after takeover, and demonstrate controlled backend replacement/rollback with the level of real evidence clearly labeled.

## Original exit criteria

- The implementation supports bounded routing, review, takeover, revocation, rollback, and backend substitution through existing server-owned authority and durable records.
- Any enabled connected route has actual one-backend evidence meeting the protocol committed before evaluation; fixture-only paths remain diagnostic/shadow.
- The release report separates one-backend scoped-routing qualification from two-implementation portability and optional self-hosted qualification; missing external evidence remains pending rather than being reclassified as a pass.
- Configuration changes cannot reuse stale calibration/qualification; the report records effective input limits, distribution/confidence semantics, and numerical/quality differences.
- Targeted affected checks and the declared model/configuration qualification cohort pass for the claimed scope; full regression is not repeated per goal.

## Evidence gate

Human-approved unavailable/optional capabilities remain explicitly excluded and disabled; excluded goals are not passed. Missing required v1 pilot evidence means beta/RC, not full M07 acceptance.
