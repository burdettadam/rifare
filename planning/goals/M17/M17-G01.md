# M17-G01 — Declare image intake scope and qualify existing upload foundations

**Milestone:** M17 · **Type:** worker_goal · **Lane:** decision_models_and_skills · **Risk:** critical

## Outcome

Establish the exact opt-in image pathway and fill the concrete gaps between the current diagnostic upload contract and permitted evidence intake.

## Before starting

1. Inspect the actual repository, installed workflow and accepted dependency evidence before writing code.
2. Resolve proposed module/test locations and bind the goal to existing commands; no invented executable commands or preclaimed application tests.
3. Use a dedicated worktree and isolated data/services; preserve the protected baseline and minimize sensitive evidence.
4. Inspect the current attachment-denying agent boundary and the existing return-intake diagnostic contract before implementation. The contract's restricted PNG/quarantine/sign/content/erase surfaces and model_access=false are reusable foundations, not proof of active qualified model intake.
5. Keep every existing attachment rejection active until a specifically authorized replacement path passes its intake and privacy checks. Do not assume previously submitted attachments exist or can be reused for inference.
6. Use licensed/authorized synthetic image fixtures and the current privacy/storage mechanisms for local work; record exact attachment versions and transformations.
7. Reuse M13/M14's decision contract, bounded evidence, budgets, provider controls, review behavior, and qualification records. Text-routing success does not qualify visual or audio/video handling.
8. Use focused intake, access, decoder-boundary, privacy, and media-adapter checks during development; evaluate the frozen media cohort at the qualification boundary.
9. Before any user media reaches a model, qualify the selected upload types, byte/pixel/decompression bounds, quarantine/processing policy, exact-case access, purpose/provider opt-in, retention, erasure, and derived-record lifecycle.
10. Freeze the image use case, allowed observations, reference labels, cohort/strata, preprocessing, metrics, targets or threshold-selection rule, and review behavior before evaluating qualification outputs.
11. Image assistance requires actual model observations on the authorized declared image cohort; fixture media and text-only model quality cannot satisfy that gate.
12. Audio/video additionally requires a named merchant need, explicit purpose and provider configuration, permitted codecs/duration/size/sampling policy, qualified processing/privacy path, and a separately predeclared measured cohort. Unselected modalities remain disabled.
13. Cloudflare Gateway text DLP cannot be assumed to inspect encoded image/audio/video content. Any DLP or content-filter coverage must be established for the actual media route.
14. Evidence-usability or condition classification does not establish authenticity, identity, intent, fraud, warranty entitlement, physical receipt, or financial authority.
