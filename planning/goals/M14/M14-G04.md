# M14-G04 — Add and verify a replaceable SystemOne transport

**Milestone:** M14 · **Type:** worker_goal · **Lane:** decision_models_and_skills · **Risk:** critical

**State:** not started · **Owner:** unassigned · **Execution:** local_then_separate_qualification

> Planning specification only. No application test, provider operation or feature completion is claimed.

## Outcome

Make the decision task callable through a second compatible serving implementation while documenting its real capabilities and qualification status.

## Bounded ownership

- Implement the narrow SystemOne-compatible transport against an approved endpoint using the same logical question/resource and result contract.
- Normalize response envelopes and backend-specific confidence metadata; record context/media limits and supported question types without assuming hosted/local equality.
- For a chosen self-hosted Clef endpoint, require evidence that the trained joint schema head and backbone are loaded and pin model/serving artifacts; otherwise keep that self-hosted capability unverified.
- Run local transport conformance without external spend. Exercise the second real implementation when available and record pending external qualification otherwise.
