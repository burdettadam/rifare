## Before starting

1. Inspect the actual repository, installed workflow and accepted dependency evidence before writing code.
2. Resolve proposed module/test locations and bind the goal to existing commands; no invented executable commands or preclaimed application tests.
3. Use a dedicated worktree and isolated data/services; preserve the protected baseline and minimize sensitive evidence.
4. Use existing packing, allocation, inventory-movement, purchase-order and budget services as authoritative foundations.
5. Select one bounded warehouse topology, supported device profile and route baseline; do not begin with unrestricted floor-plan image inference.
6. Bind supplies consumption to explicit qualified source events rather than assuming every API call consumes a physical unit.
7. Validate the chosen warehouse layout, bin identities, item placements, access constraints and operator/device workflows against the actual facility.
