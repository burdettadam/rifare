# M25-G04 — Extend media privacy and cancellation through browser memory

**Milestone:** M25 · **Type:** worker_goal · **Lane:** browser_decision_models · **Risk:** critical

**State:** not started · **Owner:** unassigned · **Execution:** local_then_separate_qualification

## Outcome

Apply the established M17 purpose and deletion lifecycle to browser image data, derivatives and observations, with explicit destination fallback and honest cleanup limits.

## Bounded ownership

- Inventory Blob/object URLs, decoded pixels, canvas/image buffers, embeddings, worker/GPU resources, caches and server client-observation records. Reuse M17 retention and privacy owners for originals/derivatives; disable persistent customer-media caching unless separately configured and qualified.
- On abort, logout, tenant/case change, source correction/erasure, expired grant, device loss or runtime revocation, stop new work, dispose controlled resources and fence late submissions with current server authority/source checks.
- Keep local image preview/inference, M17 upload, result submission and optional remote inference as separate purpose/destination transitions. A browser failure or unsupported vision companion never authorizes sending image bytes to a hosted service.
- Exercise export, erasure, restore suppression and application-controlled cache cleanup without claiming secure deletion of malicious-client memory, unmanaged browser backups or copied exports. Keep model weight cache cleanup distinct from customer-media deletion.
