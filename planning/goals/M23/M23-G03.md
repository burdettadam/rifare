## Bounded ownership

- Reuse the existing DecisionRequest types and validation semantics through the smallest browser-safe extraction. Current decisions.mts imports commerce validators with transitive node:crypto/fs/sqlite dependencies and uses Buffer for sizing; do not blindly import it or bundle the commerce kernel into the browser. Preserve exact UTF-8 sizing, membership, finite-number and rounding behavior in both environments, and keep the current v1 server contract and branded evidence meanings unchanged.
- Map bounded logical requests to Kevala and add a narrowly versioned browser result/client-observation envelope outside the existing canonical reader result. Preserve labeled confidence and unknown usage; store browser artifact revision/runtime/precision in this new branch rather than changing v1 native-transport revision semantics. The current prepare() handle is private WeakMap-backed state and is not serializable: introduce a server-issued expiring, replay-controlled preparation identity bound to actor/session, tenant/store/case/task, permitted evidence and question/configuration revisions.
- Use the existing case, permission, support-ownership, execution-stop, resource and privacy owners to issue the minimal currently readable input projection and ingest the proposal. Recheck all current bindings at issuance and acceptance, enforce request-byte/result bounds and replay/idempotency controls, and have the server create its own immutable client-observation receipt rather than accepting a client-authored canonical receipt.
- Record server-verified receipt/auth/source/configuration facts separately from client-reported model identity, execution, artifact revision, timing and answers. Reuse existing receipt/privacy storage where supported through a separately versioned record kind; public hashes and a server-created storage record do not attest browser model execution. Preserve the private canonical M13 service branding and trusted live evaluator, which must not admit browser payloads.
