# M16-G03 — Persist narrower authority before admitting protected data

**Milestone:** M16 · **Type:** worker_goal · **Lane:** security · **Risk:** critical

**State:** not started · **Owner:** unassigned · **Execution:** local_then_separate_qualification

> Planning specification only. No application test, provider operation or feature completion is claimed.

## Outcome

Make protected-data admission depend on a durable task restriction that all relevant enforcement points have applied.

## Dependencies

[M16-G01](../M16/M16-G01.md); [M02-G18](../M02/M02-G18.md); [M02-G21](../M02/M02-G21.md); [M15-G99](../M15/M15-G99.md)

Dependencies must be **accepted**, not merely assigned or implemented. Inspect current accepted evidence before starting.

## Bounded ownership

- Add an explicit task restriction version separate from lease generation, with a small monotonic state model: a task can retain or narrow authority; ordinary renewal, resume or restore cannot widen it.
- Define one concrete protected-data rule that removes an unrelated export/diagnostics route while retaining necessary approved inference, case reads and proposal/verified-recipient output operations.
- Check classification and required restrictions before releasing protected facts, including facts present in initial task input or recovered context. Apply the rule at the trusted admission point, not after the model has received the data.
- Persist the required restriction, fence prior authorizations and collect acknowledgements from each relevant branch/enforcement point before delivering protected content. Missing acknowledgements, version conflicts and unavailable state fail closed.
- For in-flight work, drain, cancel or reauthorize the affected channels according to the supported transport. Record already accepted effects as potentially irreversible and preserve their original reconciliation identity.
- Require a separately authorized task to request broader authority; transferring classified facts to a new task must retain their handling restrictions.

Additive specification from the separately retained roadmap. Concrete assignment and allowed paths require a prior maintainer record; only M13 is assigned by ADR-0042.
