# M16-G02 — Enforce one real isolation and egress profile

**Milestone:** M16 · **Type:** worker_goal · **Lane:** security · **Risk:** critical

**State:** remaining work · **Execution:** local_then_separate_qualification

> This packet describes outstanding work. Its presence, removal, or rendered state does not establish formal acceptance, production qualification, or executed tests.

## Outcome

Run the supported managed agent in a constrained environment that cannot bypass the broker to reach the network, host secrets or sibling tasks.

## Bounded ownership

- Implement one Linux/container profile with no general network path from the runner and a narrowly authenticated Unix-socket or equivalent private broker channel. Place the broker and provider/commerce credentials outside runner reach.
- Constrain filesystem mounts, per-task scratch, process namespace and privileges; prevent access to host sockets, metadata endpoints and sibling-task state. Pin the image/runtime and declared mounts.
- Set explicit CPU, memory, process-count, wall-time and output-size limits, and bind termination to task stop/deadline behavior.
- Use real local network probes and recording endpoints to observe denial. A unit stub that throws ExternalEffectDenied is evidence about application intent only.
- If a later Cloudflare Dynamic Workers profile is selected, qualify it separately with globalOutbound:null or an explicit verified egress handler; do not assume the raw runtime defaults to no network.

Additive specification from the separately retained roadmap. Concrete assignment and allowed paths require a prior maintainer record; only M13 is assigned by ADR-0042.

## Preserved acceptance criteria

- From the real isolated runner, direct HTTP/TCP/DNS or alternate network paths in the supported threat model cannot reach the recording destination, while a permitted typed broker operation succeeds.
- The runner cannot read a secret canary held only by the broker, host-sensitive mounts or a sibling task's scratch; denied attempts do not expose the canary in logs.
- A bounded over-budget process is terminated by the actual runtime limit and cannot continue broker operations after its task deadline or stop.
- The evidence records the exact image/runtime, effective isolation configuration and observed boundary, with unsupported platforms left unqualified.
