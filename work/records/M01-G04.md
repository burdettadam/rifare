# M01-G04 — Evidence-backed read capabilities

Authority: [ADR-0012](../../docs/decisions/0012-five-goal-local-implementation.md).
State: implemented for local diagnostic review; only synthetic reads enabled.

Implementation: `packages/commerce/capabilities.mts`, migration 004, and
`tests/development/commerce-capabilities.test.mts`. Effective capabilities include
action/version, adapter contract, granted scope, connection revision, market,
resource source/kind/state and explicit synthetic evidence. Unqualified real-store
adapters remain unverified even when granted read scopes. There is no live adapter
implementation or arbitrary HTTP/SQL fallback. Every commerce write is disabled.
Manual handoff and unavailable history have typed limitations, not invented data.

Execution recomputes the current capability. Removing a grant, changing the market,
invalidating a contract or deactivating a store takes effect immediately. A copied
discovery response cannot authorize a later call. UI and future agent transports
must consume this same service rather than reimplementing its authority rules.

CASE-M01-G04-01 maps to M01-G04-01 and -05; -02 and TEST-033 to -02, -10 and -12;
-03 to -03, -04, -06 through -09 and -13 through -15. Fifteen tests run with:

```sh
node --experimental-strip-types --test tests/development/commerce-capabilities.test.mts
```

Synthetic contract evidence is an identified local fixture contract, not a signed
platform certification. Qualified message history, native Shopify reads, MCP and
React UI remain in their assigned later goals. No model-specific implementation,
prompt authorization or cached positive permission is introduced here.
