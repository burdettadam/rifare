# M07-G16 — Locale and timezone presentation development

Assigned before implementation by ADR-0035, at
`8b249fae2b1e1bb448aa74e8d870ce1933f4f7f6`, from retained main
`0748116fe58901d318bf2f0d9c30fd35a8005d43`. The locale author is the sole writer
on `goal/M07-locale`; root owns integration, registrations and source inventory.
Separate nonauthor authority/security and regression sessions review the actual
integrated candidate and evidence.

This implements the bounded local preparation described in
`docs/LOCALE-PRESENTATION.md`. Status and returns gain explicit locale/timezone
controls, exact currency formatting and UTC/policy-zone labels. Unsupported or
ambiguous formatting inputs are rejected. The original return evaluator, all
deadline arithmetic, source amounts, API payloads, session generations and
confirmation controls are retained. Preferences are not persisted. There is no
new financial action, migration, dependency or service.

Fifteen new native cases and the small browser fixture were committed first at
`73b1cd4`. Independent literal money/instant goldens and a targeted localized-
decimal parsing fault specify the behavior. The author did not run native tests;
root runs the coherent focused development selection and retains actual results.
The browser fixture uses actual static assets and a bounded loopback API bridge,
including an explicitly labeled damaged-response negative case. No source effect
is inferred from a damaged or synthetic success response.

This work is submitted for review, not self-accepted. Formal M05/M06/M07
prerequisites, human assistive-technology observations, translations, connected
service/merchant work and the React/PostgreSQL target remain blocked. Rollback
uses native Git and needs no data migration. Exact source/run/review pins are
recorded in accompanying integration evidence rather than in report-only commits.
