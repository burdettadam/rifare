# M07-G12 local development handoff

State: ready_for_review; formal external qualification remains blocked.
Prior assignment: ADR-0034, base `aaf4943` (previous main `6dfd508`).
Author: recovery/load worktree, branch `goal/M07-recovery-load`.

Optional immutable webhook intake limits preserve the original unlimited default.
Authenticated admission checks merchant-wide unconsumed count/bytes inside the
existing persistence transaction. Duplicates keep their durable acknowledgement;
new over-capacity requests receive HTTP 429 and Retry-After without acknowledgement.
No new migration, deletion, worker scheduler or automatic provider retry is added.

The frozen twenty-event local workload reports actual hardware, elapsed intake and
processing times, queue/consumption lag, real bounded retry waits, and exact
accepted/persisted/consumed identities. It preserves nonaccepted exhausted events
as a failure. Baseline comparison requires a separately retained hash and the same
workload/hardware/runtime/capacity; a candidate cannot hide degradation by changing
the workload. The report's evidence consistency is not approval authentication.

Ten admission/load cases plus one shared CLI case in the eighteen-case combined
file cover the three CASE-M07-G12 obligations, persistence failure, duplicate
acknowledgement, competing/reopened processes, scopes, actual HTTP backpressure,
bounded exhaustion and workload/pin/latency faults. Tests were written first;
native execution is deferred to the integration owner's single focused selection.
No author pass, independent review or formal acceptance is claimed here.

See `docs/RECOVERY-LOAD.md` for commands and rollback. The measured pending budget
does not bound retained history/disk. Every deployed intake process must carry the
same configuration. Approved sustained workload/hardware, connected waiting,
target PostgreSQL and production qualification remain open.
