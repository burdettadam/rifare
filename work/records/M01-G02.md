# M01-G02 — Verified customer access

Authority: [ADR-0012](../../docs/decisions/0012-five-goal-local-implementation.md).
State: implemented for local diagnostic review; target-stack acceptance is open.

Implementation: `packages/commerce/customer-access.mts`, migration 002, and
`tests/development/commerce-customer.test.mts`. The transport is an explicitly
server-injected local test delivery channel, not an implemented email provider.

Order number and email initiate a generic response, never grant access. A random
single-use proof goes only to the matched source customer's address through the
trusted delivery channel. Only its hash persists. Challenges have a five-minute
lifetime, five verification attempts, per-target and per-client issuance limits,
store/order/customer binding, and an owner-version fingerprint. Verification
atomically consumes the challenge and issues a hash-backed session limited to
one order for fifteen minutes. Logout invalidates the server-side session; replay
cannot restore it. Delivery failures leave unusable challenges and generic replies.

CASE-M01-G02-01 maps to M01-G02-01; -02 to -02, -04 through -12 and -15;
-03 to -03 and -17. Eighteen native cases also check response shape, persistence,
foreign attachments, cleartext absence and delivery failures. Run:

```sh
node --experimental-strip-types --test tests/development/commerce-customer.test.mts
```

Local HTTP will use header tokens and no-store responses. Production TLS,
authenticated email delivery, distributed abuse controls, account recovery and
timing-side-channel qualification are not claimed. Invalid and nonexistent
accounts have identical public response shape, not a proven constant-time network
response. Raw tests and targeted fault demonstrations are separate evidence.
