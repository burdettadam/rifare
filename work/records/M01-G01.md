# M01-G01 — Tenant-scoped canonical resources

Authority: [ADR-0012](../../docs/decisions/0012-five-goal-local-implementation.md).
State: implemented for local diagnostic review; M00 target prerequisite remains open.

Owned implementation: `packages/commerce/kernel.mts`,
`migrations/commerce/001-foundation.sql`, and
`tests/development/commerce-resources.test.mts` with the shared fixture helper.

The server issues opaque, random operator/worker sessions after trusted local
membership provisioning. Only hash verifiers persist. The kernel authenticates
sessions into nonserializable scopes and revalidates expiry, membership, tenant
and store on every operation. There is no default or caller-chosen tenant.
Resources retain composite ownership, source key, version and observation facts;
queries, jobs, attachment references and the audit view all carry that boundary.
No HTTP provisioning or commerce write is exposed. Database administration remains
trusted; this code is not a sandbox against arbitrary native code holding the DB.

CASE-M01-G01-01 maps to M01-G01-01 and -04; CASE-M01-G01-02 and TEST-002 map to
-02, -04 through -11 and -17; CASE-M01-G01-03 maps to -03 and -09.
Seventeen native cases are bound to the registry. Run:

```sh
node --experimental-strip-types --test tests/development/commerce-resources.test.mts
```

The fixture uses real temporary SQLite files and independent alpha/beta expected
values for identical source order IDs. Raw TAP and later fault/review evidence are
retained separately from Git. Source rollback is the goal parent; restoring an
older application against a newer database requires the documented backup path,
not deleting migration rows. PostgreSQL, web login and external identity providers
are not qualified by this implementation. No-AI operation is inherent.
