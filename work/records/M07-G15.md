# M07-G15 — Accessible workflow development

Assigned before implementation by ADR-0034 from main
`6dfd50853525c707138e52673c32ce71707f9ad4`. Root owns this UI worktree and local
integration; separate nonauthor sessions supply authority/security and regression
review. The goal remains unaccepted pending its original prerequisites and actual
human assistive-technology qualification.

Implemented six existing diagnostic pages with a shared presentation-only helper:
skip navigation, native field error associations, distinct status/error
announcements, focus after critical state changes, contextual recovery action
names, visible focus and narrow-screen layout. Existing confirmations, API
payloads and server authorization remain intact. The server change only serves
the two new static assets; the separately assigned G12 author owns webhook
capacity/error handling.

Eight new native cases bind to the actual local APIs through a browser bridge.
The semantic/validation case covers all six pages; the targeted fault case removes
the real approval name and Tab reachability and requires detection. Existing
browser tests and fixtures are retained without change. Tests were written before
the implementation. Exact current candidate results and reviewer observations are
in ignored evidence and the cumulative checkpoint, not asserted by this source
record. Read `docs/ACCESSIBLE-WORKFLOWS.md` for paths, commands and limits.

Source rollback uses native Git to revert these scoped UI changes. It requires no
schema migration or data rewrite. Human screen-reader, real touch-device,
connected-service, target-stack and formal goal acceptance remain blocked.
