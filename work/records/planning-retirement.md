# Retire landed planning

## Scope and authority

The owner requested removal of goals and milestones whose code has landed, with
architecture and Git history supplying continuity. ADR-0065 records this
development-maintenance decision. The pre-cleanup base is
`d1fb45b94e14b276f7fa6e04f50173fe8cf39c77` on `docs/portfolio-branding`.

Two source audits checked M00–M12 and M13–M25 against current modules, contracts,
native test registrations, work records and introducing commits. A separate
tooling audit traced generators, validators, frozen contracts and distribution
membership. The audit found genuine remaining target-stack, real-adapter,
image-path and loyalty implementation, in addition to external qualification.

## Result

- 281 goal packets become 55 active packets: 47 worker scopes and eight future
  integration gates. Ten packets are narrowed to their unfinished portions.
- 27 real-adapter gaps are consolidated into short integration entries in the
  same canonical input and catalogue; no extra per-goal files are generated.
- 26 milestone sheets become 13 active/follow-up groups. Historical gates remain
  unaccepted unless the existing acceptance flow says otherwise.
- 226 goal cards, 13 completed milestone sheets and five duplicate initial
  backlog/roadmap/state/scheduling files are removed: 244 source deletions.
- Architecture maps current source through M20-G03. The current plan, roadmap
  and qualification guide replace the chronological active planning narrative.
  Completed packet text stays in Git; there is no new in-tree archive.

## Preserved authority and behavior

The 949 behavioral specifications, 216 requirement mappings, 57 target identities,
frozen source criteria, native implementation and existing executable test
registrations remain intact. Active packets retain their original acceptance
criteria and formal dependency IDs. Historical owners are resolved from the
retained specification inventory, including retired workers needed by a future
G99 gate. Missing acceptance never becomes true because a packet was removed.

The registry replaces 141 retired-card capability references and 197 protected
planning paths with the retained behavioral specification contract; existing
runtime/oracle contracts and capability states remain unchanged. Two focused
plan-helper cases are added. Registry/source membership and pilot-checker hashes
are refreshed for this explicitly reviewed migration. The regression controller,
trusted baselines, acceptance ledger, release thresholds and licensing obligations
are unchanged. An old exact-path baseline will require reviewed migration; no
full regression-gate pass is claimed.

## Verification and review

The focused repository, plan and browser-plan helper selection passed all 60
tests in 18.698 seconds under one 60-second invocation deadline. Planning
validation, generated views, repository links, workflow checks and whitespace
checks passed. After staging the authorized deletions, distribution review passed
for 1,683 source files across the same six components.

A source comparison checked 412 protected behavior/reference files, including
all 284 native development test files, without a change. All 3,292 existing
registered test objects are byte-for-byte equivalent as JSON objects; two plan
helper cases bring the registry to 3,294. All 222 capability metadata records,
active goal criteria/dependencies/test bindings, component licensing metadata and
non-count licensing-oracle fields are unchanged. Every current registry path
resolves. The known envelope/benchmark commands produce the same failures as the
original development checkout.

Raw results are under ignored `evidence/planning-retirement/`. Independent scope
and regression reviews inspected candidate
`bec7e125a44358d9e728285dbf42351d51c6c71a`
(tree `d91800f393cb5cc19417719111e5d8d4f938c440`). Scope review found no blocking
authority or coverage issue. Regression review found one continuation issue:
compact integration owners are absent from current active goal objects, while
the existing workflow/evidence tools correctly require a packet at their trusted
base. Planning maintenance, dispatch, current-plan and agent guidance now require
promoting only the selected original contract into a bounded active packet and
committing that assignment before choosing the execution base. The controllers
remain unchanged.

Both independent reviewers approved corrected candidate
`006bde5a4d799f745caff34d6bbf17783199f8bc`
(tree `4b9b093c2572adfa4e089d1e78aa87e5561c77c2`):
`landed_foundation_audit` for authority/scope and `retirement_regression_review`
for regression. The continuation finding is resolved with no outstanding
blocking findings. Reviewers confirmed the correction changes only five

closure records those decisions; it changes no implementation or planning data.

## Existing limits

The release-benchmark/envelope mismatch predates this task: 44 original target
dispositions versus 57 targets, plus the original 676-specification source pin
versus the current 949-specification document. The cleanup changes only historical
goal lookup in those checkers, preserving the failing boundary and frozen inputs.

No product runtime, provider, physical, browser, model or production qualification
is established by planning maintenance. GitHub integration write access remains
unavailable; the handoff bundle preserves the local commits for authenticated
import and review.
