## Privacy and independent review

Subject exports filter every new table by tenant, store and owning resource.
Erasure removes private scan/operator/source/parcel and manifest payload copies,
revokes label approvals, and preserves original scan/unit/purchase identities
plus exact minimized monetary/void/refund audit. Mixed-customer parent JSON is
avoided. Repeated minimization reconstructs an allowlisted audit even when an
imported record already carries a redacted flag.

Merchant import and snapshot restore retain the existing schema-bound protocol,
replay current suppression and revoke new label approvals. Restored execution
remains quarantined; separate fixture databases and copied artifacts require
operator cleanup and are not claimed physically erased by commerce SQL.

Early nonauthor inspection found two concrete risks: losing a named warehouse
binding could resemble an unconfigured legacy source, and trusting an unchecked
redacted flag could retain private payloads. Root added expected binding
presence/digest checks and a durable source requirement marker, and made shipping
minimization validate integrity and reconstruct only the allowed audit fields.
Existing new cases cover both without increasing the planned case count.

observation when an authentic carrier event names the same confirmation,

manifest admission. Independent authority inspection found that an older
purchase receipt could mask an uncertain void during erasure; minimization now
retains the original durable `void_id` and unknown stage until a matching
receipt has observed it. Existing shipping cases cover these boundaries.
