## Implemented behavior

`packages/conformance/compatibility-matrix.mts` reads the existing exact-source
adapter catalog and scores original observations with the existing evaluator.
Each row binds provider/model/weights, skill/profile, runtime/engine/source,
platform/payment/fulfillment versions, model capabilities, scopes and current
configuration/policy/prompt digests. Missing, expired, revoked, copied or changed
inputs remain unsupported. Freshness is bounded to 24 hours and actual current
source files are checked. Runtime readiness recomputes from current inputs.

The existing conformance report's source snapshots are rechecked against its
independent fixtures, source digests, record counts and expected source fields.
Direct-only coverage does not infer native-only operation proof. Review records
must bind the exact subject, requirement and evidence, come after observations
and name a different reviewer; these supplied records do not authenticate
external identity or manufacture acceptance authority.

The read-only score is independent of a broader failed scope. All non-read-only
tiers still require existing action-specific SupportQualification and execution
checks. No matrix label grants an action, role or endpoint. All outputs preserve
`execution_authorized: false` and `production_qualified: false`.

`tools/compatibility-matrix.mts` exports the current 25-adapter, 123-operation
version/scope envelope without starting a catalog/native test run or provider.
With original evaluation/conformance/review inputs it emits minimized per-tier
rows and exact normalized source report hashes. An unsupported row exits 1.
No credentials, source payloads or customer facts are included in the matrix.
