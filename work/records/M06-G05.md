# M06-G05 — Verified gift-recipient choices

Assigned to `/root` under ADR-0028, branch `goal/M06-first-five`, base `45fdd7b`.
State: ready for independent final review; formal prerequisites and connected proof remain open.

Write scope: additive `gift-proof.mts`/`gift-returns.mts` and migration 023,
canonical case verification, selection/financial outcome restrictions, privacy,
the existing HTTP service, new regression tests and portable contracts/demo.
Never give the recipient an ordinary purchaser session or rewrite purchaser
identity. Use source-derived recipient proof, allowlist projections, existing
case/request/unit ledgers, staff approval and final current-state checks.

The allowed gift outcomes in this bounded slice are exchange or native credit
to the verified recipient. Additional collection and cash refunds require a
different qualified journey and remain denied for recipient cases. A free item
does not bypass reservations, current proof or approval. No raw customer tokens,
messages, prices or source data belong in committed evidence.

The implementation uses separate delivery proofs and recipient views, canonical
request/approval/unit records, native recipient credit and stock-hold recipient
binding. The credit source pins the approved operation, allocation and native
return before transport, so omitted recipient fields cannot credit the purchaser.
Independent review exposed this boundary; seven permanent tests cover omitted
fields, substituted identifiers, immutable beneficiary binding and a separate
purchaser return on the same order. Proof renewal keeps request identity and
revokes old approvals. Erasure
preserves quote and monetary reconciliation context; recipient/purchaser and
historical-recipient retention holds protect evidence. Staff cancellation and
warehouse disposition retain their existing authority and approval controls.
Permanent tests include two separate processes racing for the same original gift
unit, recipient erasure after lost native/credit/replacement responses, recipient
and purchaser export boundaries, and dropped or substituted native gift bindings.

Independent preflight failures and fixes are retained, including parcel primary
key handling, recipient evidence holds, catalog exclusions and lifecycle action
compatibility. They are not hidden or counted as passes. Exact-candidate native
reports, targeted mutants, independent review decisions and the eventual local
merge decision travel with the handoff. The public gift UI selects a choice to
discuss with the store; staff preparation is still required before submission.
Previously sent obligations are not automatically repriced or reauthorized by
proof renewal. See `docs/exchange-depth.md` for setup and operational limits.
