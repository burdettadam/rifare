# M11-G03 local implementation handoff

Assigned under ADR-0040 from protected product `8096abe27043852d86295b15d4708875fd1434de`.
The forecast author owns this isolated branch and no acceptance or production
authority. M07-G99, M08-G99 and original worker acceptance remain open.

Implemented: stored per-SKU/horizon forecast references, exact dataset/backtest/
catalog pins, measured baseline fallback, empirical residual envelopes, unsupported
history states, independent current review, expiry/revocation and restore handling.
Procurement receives the real `InventoryForecasts(k).assertReviewed` API with only
a stored ID/digest as input. It cannot supply a model-confidence or approval flag.

Owned source is `inventory-forecasts.mts`, `forecast-privacy.mts`, shared new core,
`inventory-forecasts.v1.json`, and the forecast/review tables in migration 042.
All five forecast tables are merchant aggregate data. Canonical customer export
is empty; explicit nested allowlists and global/store review revocation are
provided for root's canonical privacy/import/recovery wiring.

CASE-M11-G03-01/02/03 and two additional quantity/authority cases were committed
before implementation in `0e04437`. The named fault replaces measured improvement
with a high confidence score. The independent fixture requires baseline retention
when the candidate's MAE is one and the baseline's is zero. Zero denominators,
integer bounds, same-store resource identity, current reviewer permission and
restored review revocation are exercised within the same 12-case file.

Author product executions: zero. State: implemented for root's bounded validation
and independent review. An empirical envelope does not qualify probability coverage
or merchant performance. No automatic PO, financial effect, stock movement, paid
model or real external interface is introduced.
