## Architecture and dispatch boundaries

M23 plans an optional, explicitly selected desktop-browser Clef Flash Q8/Kevala
text/JSON path. M24 plans a separately verified compact Wllama/GGUF candidate.
M25 plans browser image evidence after the existing M17 media and privacy gates.
Preserve the logical decision contract, the trained joint decision path, pinned
artifact/runtime identities, strict output validation and explicit provenance.
Client-submitted results remain untrusted observations. Server authority, source
access, current task checks, approvals and effect identity remain canonical.
Existing M13 hosted evidence and M14 calibration/SystemOne/routing controls are
preserved. Browser results cannot mint trusted inference or automatic routing.

Browser-safe contract extraction and new versioned ingestion are future work;
the current Node-oriented modules are not presented as browser-ready. Artifact
cache and customer-data persistence are distinct. Purpose, cancellation, bounded
resources, cache removal and explicit local-to-hosted fallback remain required.
No image, mobile, offline task-access, trusted browser execution or model-quality
claim follows from a loader or a fixture. Actual runtime/device inference,
fidelity, privacy and applicable formal qualification require their own evidence.

The handoff recommends M23-G01–G05 as the next browser implementation batch after
the current assignment is coherent. Record that recommendation separately from
the canonical dependency queue. All new goals remain `not_started`, `unassigned`
and `not_run` until a later bounded implementation assignment. M15 remains the
earliest unassigned existing sequence; no existing goal or prerequisite is skipped
or accepted by this planning update. M14 and inherited formal/connected gates
remain open exactly as recorded in the protected checkpoint.

Local nonrelease integration and delivery of this updated project are within the
owner's delegation. Production/paid effects, publication, account changes,
messages, release tags, model downloads and enabled browser execution are outside
this planning assignment. A cumulative checkpoint preserves the unchanged M14
archive, both roadmap revisions, all native Git refs and actual adoption evidence.
