# ADR-0016 — Structured policies, tailored profiles and trusted instruction bundles

The owner assigned the next five goals and delegated implementation, judgment,
review and local merging. Base main: ddfcbb6. One writer owns
`goal/policy-customization-batch`. This checkpoint precedes implementation.

Implement M02-G03 through M02-G07: structured policy versions, the commerce manifest,
deterministic configuration layers, a manual draft editor/simulator and constrained
instruction/resource installation. Reuse the existing server authority, SQLite
repository, skill content interface, native test runners and external regression gate.
No scheduler, mandatory model, package dependency or public/paid operation is added.

Continue diagnostic ordering despite M00/M01 target qualification remaining open.
DELEGATED-LOCAL-07 permits the documented same-assistant maintainer security and
regression review for this nonrelease integration. It does not represent independent
review sessions, full prerequisite acceptance, PostgreSQL/React qualification, or
permission to reduce tests and acceptance thresholds. This exception must not be
used to approve policy changes by an agent inside the product.

Existing legacy skills/profile contracts stay compatible. New imported bundles use
explicit scoped origin/digest approval; no scripts or network capability. Draft
simulation never activates policy. Structured policy review must use a different
actor from its author and publication is separately owner-authorized. Policy
revocation remains effective for previously pinned cases. Existing money and
permission behavior remain protected.

Allowed changes: additive commerce modules and migration; explicit role actions;
server routes and a no-model draft editor; a versioned JSON schema and synthetic
fixtures; new native and browser-component tests; registration/inventory additions,
work records and concise documentation. Preserve all previous test sources and
registrations. Review source-count additions and any protected change explicitly.
No remote, release tag, live store, model call or production data is authorized.
