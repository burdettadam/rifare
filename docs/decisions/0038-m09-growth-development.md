## Required behavior

Shopping uses current source catalog identities, prices, inventory and approved
terms. Model text grants no cart, discount, checkout or payment authority. Upsells
extend the original order/fulfillment and its existing stock, approval, hold,
payment and acknowledgement path; customer acceptance is explicit and repeatable
without a second fulfillment or uncertain payment. Existing replacement/address/
cancellation semantics remain intact.

Checkout assignments are durable, scoped and stable across frontend reorderings;
version and eligibility changes have explicit rules. Declared randomized
assignment and immutable holdout differ from the existing nonrandom prevention
diagnostic. Exposure and conversion units, windows and denominators are pinned.
Attribution, holdout-estimated effects, contamination, uncertainty, refunds and
contribution margin remain separately reported. No automatic winner promotion.

Campaign authoring remains a proposal. Approval binds the exact content, source
facts, audience definition, sender, schedule, budget and offer. The established
send boundary rechecks current consent, suppression, ownership, authority and
recovery immediately before egress. Partial/unknown sends preserve original
logical operation IDs and repair only through original-source lookup. A provider
acceptance is distinct from observed delivery. Segments never join tenants or
guess absent source data. Recovery rechecks purchase and consent at final send.

Email GET/HEAD/prefetch is read-only. Confirmation requires current authenticated
customer identity, an unexpired scoped token, current preview and an explicit
state-changing request; token possession is not customer authority. Repetition
cannot repeat an irreversible effect. Unsupported operations stay disabled.

Catalog visibility records actual permitted-interface fixture observations with
prompt/catalog/model/configuration identities and historical baselines, never
placement guarantees. Catalog writes require independent current merchant
approval and exact source revision; protected prices or invented certifications
are rejected. Rollback is a new reviewed, conflict-aware change, not a blind undo.

Optional media has purpose-specific consent, approved destination/model/settings,
bounded retention, revocation/deletion and queued-task rechecks. Return evidence
cannot be repurposed. Only synthetic authorized fixture media is processed here;
content cannot grant authority. Outputs remain labeled generated, with no fit or
return-policy guarantee. Changed model/settings invalidate qualification. Identity
resolution is disabled without current scoped readiness, provenance, purpose,
geography and opt-out handling, with no local cross-merchant identity graph.

Each new table has explicit tenant/store/resource or subject scope, export,
erasure/minimization, restore/quarantine and audit behavior. Minimized original
effect identity must survive erasure, while approval and consent never survive as
replay authority. Separate source stores and caller copies retain explicit cleanup
responsibilities. Preserve the prior documented post-erasure inventory limitation.

The protected base contains 1,322 tracked paths, 2,797 registrations, 147
capability objects, 186 commerce tables, 35 migrations, fifteen privacy surfaces,
211 runtime source pins, 28 adapter declarations, 141 operations, 146 declared
native cases and 47 direct fixtures. Preserve every prior member, behavior,

planning/goal packets unchanged. New executable cases and proposed capabilities
are additive. Connected/partner preparation receives distinct local IDs and does
not register the unperformed original formal cases as passing.

Before implementation, this assignment authorizes necessary additive current
table/migration/catalog counts and schema/hash membership updates in the same
five retained tests: privacy coverage, return portability, installation upgrade,
adapter catalog and compatibility matrix. Preserve the immutable 170-table,
shipping-eight and frozen 178-table obligations, add an independently frozen
186-table projection, and retain the legacy 167 projection and all seven existing
storage contracts byte-exact. Keep old rollback and behavior assertions.

New adapter modules must be declared with honest local/unavailable semantics.
Retain all old operations, native case members, direct requests/outcomes, source
pin targets and scope conditions. Assigned source/test changes may refresh their
exact hashes and dependent version descriptors. These are metadata updates, not
connected qualification. If the additive catalog reaches the current bounded
JSON decoder ceiling, introduce a separately bounded catalog reader sufficient
for the complete additive inventory; retain the generic decoder's limit and all
old catalog validation requirements. Do not remove obligations to fit a byte cap.
Independent regression review must assess every such change before integration.

## Focused evidence and review

Keep the owner's **60 actual cases, four whole files and one total 60-second
deadline per invocation**. The planned coherent selection is 15 shopping cases,
24 marketing/measurement cases, 12 optional-provider cases and the existing nine
privacy cases. These counts are a development budget, not formal acceptance
coverage. Authors write behavioral tests first and commit them before product
implementation. They run no independent product suites or demos. Root runs the
coherent integrated candidate once, then repeats only whole files affected by a
concrete failure or consequential correction.

Each goal's named unsafe behavior is exercised by an actual changed isolated
module/source and a fixed independent assertion within the selected cases.
Import/syntax errors, zero cases, copied result changes and skipped tests cannot
serve as behavioral fault evidence. Native reports retain all actual case IDs,
source/configuration bindings and executed totals. Static metadata checks do not
claim product execution.

The blocked G99 assessment does not trigger a broad regression, controller,
browser, nested catalog, restoration, connected or release campaign. Formal
acceptance still requires its original evidence. Fresh nonauthor authority/
security and regression review the exact candidate and native records without
duplicating suites. Resolve concrete blockers within at most three corrective
rounds. Root makes a separate bounded local integration decision and preserves
native history, all current evidence and the byte-exact prior cumulative archive.
