# ADR-0022 — Mixed return resolution and fixture-only financial workflows

The owner assigns the next five goals, M03-G06 through M03-G10, from `e86beee`.
The existing explicit delegation authorizes local decisions, maintainer review,
and nonrelease integration. This checkpoint precedes implementation. One writer
owns `goal/return-resolution-batch`. Same-assistant review is disclosed; no separate
reviewer, prerequisite acceptance, provider consent or real settlement is invented.

DELEGATED-LOCAL-13 permits bounded diagnostic work while PostgreSQL/React and live
provider qualification remain open. Add a shared per-unit resolution ledger, exact
paid-allocation quotes, approved synthetic refund/credit execution with durable
unknown outcomes and read-only reconciliation, and stock-aware exchange quotations.

and recovery guards. Native financial effects are restricted to an explicit fixture
source in a separate SQLite database. No live transport, payments, publication,
model call, release tag, dependency or worker scheduler is authorized.

Owned paths: additive commerce modules, one additive migration, targeted gateway
and stop/HTTP hooks, new fixture source, tests/demo/contract, inventories and goal
records. Preserve all prior executable tests, registrations, oracle expectations,
source paths, package inputs and branches. Inventory growth is only for enumerated
additions. New passing diagnostic registrations may be retained after review, not
used to assert connected financial qualification or formal milestone acceptance.
