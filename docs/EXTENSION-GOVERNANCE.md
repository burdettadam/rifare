# Extension contribution and retirement review preparation

This is the local G06 PREP protocol under ADR-0041. It does not adopt inbound
licensing terms, grant rights, authenticate a human policy decision, solicit an
outside contributor or authorize public release. The protected licensing policy,
rights-holder decision, original acceptance conditions and contribution-intake
block remain unchanged.

## Contribution review record

A scoped proposal identifies the immutable artifact, source/content identity,
declared owner and support owner, declared license, exact notices and provenance
references. It lists required typed actions and binds the actual host contract,
source, fixture and retained test versions. The store reviewer sees the real
validator scope: instruction contract validation or retained host adapter pins.
Neither is an external conformance report.

The proposer cannot supply a green flag or a reviewer name to grant approval.
The existing current Scope and permission records determine the reviewer. Review
binds the immutable artifact, current permission revision and expiry. Installation
and version activation recheck that authority. Unknown licenses, changed content,
missing notice bytes, incompatible SDK/actions or missing required host tests
block before installation.

An external contribution still needs attributable ownership/provenance, the
applicable rights decision, independent execution observations, supported contract
and evidence versions, and genuine support responsibility. The synthetic fixture
owner `synthetic_contributor` is explicitly not such a contributor. G07 preparation
tracks those missing obligations separately.

## Version notice and retirement

`proposeRetirement` records one exact existing version, optional named replacement,
versioned notice, effective time at least one day after proposal, verified inert
export digest, retained reader, the named retain-pins/repreview migration strategy,
and the required host test membership. It computes affected goal and current-store
scope from the artifact/service context. `reviewRetirement` requires another
current `skill.review` actor and rechecks those exact source and export bindings.

Instruction obligations include the three retained host manifest-contract cases;
the proposed artifact cannot replace that mandatory list with its own smaller
denominator. Adapter obligations come from the selected host catalog operations
and their actual pinned native test members. Dropping a protected member blocks
review. Deprecation cannot silently remove old readers, case captures, portable
exports or migration history.

These local retirement records are review preparation. They do not delete code,
change the protected regression registry, remove old native tests, or publish a
notice. A public retirement/release still needs the real adoption and release
decisions against the independently protected baseline. The local proposal makes
the concrete notice/export/migration/test obligations reviewable without creating
that decision on the human's behalf.

## Security and support response

The support owner is responsible for publishing attributable issue and version
notices through the separately authorized ordinary source/distribution channel.
Current local store owners may revoke an installed exact digest immediately with
the original SkillReleases revocation. That prevents further use in that store;
the archive, case pins and original effect receipts remain retained. Other stores
must make their own scoped decisions. No agency or package metadata becomes a
global administrator.

Recovery revokes copied review and activation authority. Uncertain operations
retain their original IDs and outcomes for source reconciliation. Repeating an
installation, changing an extension version, or rolling back presentation cannot
authorize replay of a financial, physical or messaging effect.
