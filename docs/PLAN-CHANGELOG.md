# Decomposition decisions and source preservation

This pack decomposes, rather than replaces, the October 15 roadmap. It retains M00–M12, M07 as the first competitive v1 gate, all 151 original requirement IDs and acceptance criteria, all 67 source scenario IDs/expectations and the original milestone exit criteria.

## What changed

The original backlog had representative broad test mappings and milestone-level dependencies. This pack adds 190 bounded implementation/decision/qualification goals, 13 integrated acceptance gates, concrete goal dependencies, exact scenario ownership, 609 additional goal-specific positive/negative/regression specifications, required evidence and permanent feature obligations.

Every goal has a named deliberately broken behavior its tests must detect. Original scenarios are mapped to semantically appropriate owners rather than inheriting a generic milestone test list. The helper validator checks original expectations have not changed.

## Scope interpretations made explicit

**M01 is read-only.** The REST/MCP and no-AI proofs cover current read workflows, not unbuilt future financial actions. M02 completes proposals/leases/authority; M07 qualifies real cross-runtime write continuity and platform parity. Foundational obligations extend to every later action.

**Hostile attachments develop in stages.** M01-G17 tests the available untrusted-content boundary and denies active/unsupported uploads. M03-G02 implements/qualifies actual evidence upload handling. The original TEST-026 remains owned at M01 with M03/media extension obligations; an early text fixture cannot qualify a later file pipeline.

**Missing history stays explicit.** M01 capability tests preserve the unsupported-history scenario; M05-G02 extends it to a real helpdesk. Absent outgoing history is not proof the customer has not been answered.

**Portability is a shared supported subset.** Two providers inside one orchestrator do not prove runtime independence. Two actual commerce adapters must qualify shared behavior, while native versus local RMA and manual versus gateway-settled refund status remain distinct.

**Gift flows receive an explicit subgoal.** M06-G05 makes the roadmap's gift-flow scope concrete with recipient verification and purchaser privacy; it contributes to existing advanced return/exchange requirements, not a new unrelated product.

**M03 merchant sign-off is not waived.** It remains in the original M03 integration gate even though component goals can be built against test systems. M07 actual pilot observations remain separate from the instrumentation goal and cannot be completed synthetically.

**Late duplicate receiving is extended.** The original duplicate-scan/partial-receive scenario is introduced in M08 packing and extended to return receiving, transfers and PO receiving; one scan UI test cannot qualify every inventory path.

**Partners are real prerequisites.** Coverage, cross-border guarantees, hubs, eligibility/payment, network alerts and identity providers require actual authorized readiness evidence. Missing contracts are not implemented by a SKILL.md file.

**Code mode stays optional.** M12-G08 makes a go/no-go decision; M12-G09 is conditional. A no-go is a valid reviewed scope decision, not a passed sandbox implementation.

**No timeline or staffing promise.** Dependency waves are not sprint/date commitments. Review counts and rounds remain configurable through the installed git-agent workflow. No remote repository or issue tracker was modified.
