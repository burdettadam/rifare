# Candidate-bound evidence contract

## Evidence root and identity

Proposed location: `evidence/<goal-id>/<candidate-sha>/`. Bind to the installed project's actual convention rather than creating a second storage system. A ready-for-review bundle identifies goal, branch/base/source SHA, source-tree digest, build/artifact digest, lockfile/dependency versions, actual timestamps and execution environment.

Record skill, profile, policy, action contract, adapter/API, runtime and model/settings pins for the tested scope. Document inapplicable fields with a reason; do not use “not applicable” for an unperformed required connected test.

Evidence may be held in an authorized artifact store rather than Git. Store stable references and hashes, and preserve access for reviewers. Never commit provider secrets, uncontrolled customer data, private merchant policies or unredacted personal records to a public repository.

## Minimum bundle

| Artifact | Required contents |
|---|---|
| `manifest.json` | Candidate/build/configuration identity; fixture, source-record, report and demo hashes; required scenarios; actual observed environment. |
| `tests/native-report.*` | Original output from the actual unit/contract/database/browser/evaluation runner. No hand-authored replacement. |
| `tests/results.json` | Normalized stable IDs mapped to unique native runner cases; discovered/executed/failed/skipped counts; real command and exit status; original-report hash. |
| `red-green.md` | Before/fault candidate and actual behavioral assertion failure; repaired candidate and passing execution; mutation validity and evidence. |
| `demo.md` and trace/recording | User/API journey on the same candidate, expected versus observed behavior and linked source outcomes. |
| `reconciliation.json` where required | External request/operation IDs, authoritative accepted/settled/received state, before/after amounts/quantities and remaining discrepancies. |
| `regression-review.md` | Independent findings about previously accepted behavior, removed/modified tests/oracles, compatibility, selector/threshold changes and required reruns. |
| `security-review.md` | Independent tenant/identity/permission/secret/egress/approval/physical-effect review and remaining risks. |
| `handoff.md` | Files/commands, limits, actual state, recovery/rollback, blocked external requirements and next dependency-ready work. |
| Protected decision reference | Trusted reviewer/maintainer acceptance bound to the candidate; not a self-authored boolean in this bundle. |

The supplied `templates/evidence-manifest.DRAFT.json` is intentionally incomplete. It is not passing evidence. `templates/evidence-manifest.schema.json` describes the proposed ready-for-review shape; M00-G08 must implement actual artifact/hash/path checking and protected identity integration in the real repository.

## Native reports and fake green results

The normalized report must derive from actual native runner output, including zero-test and skipped-test states. The trusted workflow must verify the report hash and its provenance, not merely accept a JSON file that says “passed.” Stable case IDs must map to real executed native cases; parameterized variants retain discoverable identities and explicit expected counts.

A source/evidence digest is integrity metadata, not proof that the content is truthful. A file saying that a human approved something does not authenticate that human. Review decisions come from the protected review system or another authorized independent mechanism.

When tests/code/configuration change after capture, regenerate affected results and demos against the new candidate. Re-running only the newly added test is insufficient when shared infrastructure changed. Milestone gates use one integrated candidate and the current accepted baseline.

## Financial and physical stages

Report exactly the state observed: request prepared, provider accepted, processor settled, label purchased, refund confirmed, parcel delivered, warehouse received, item inspected, replacement fulfillable or shipment accepted. Do not collapse them into “success.”

For refund/label/capture races, include provider-side effect counts and corresponding local operation IDs. An HTTP mock's counter proves the local fault-handling test, not real processor settlement. For a warehouse hold, observe that the qualified downstream process respects the hold; a stored tag or successful API request is insufficient.

Source snapshots must be synthetic or explicitly authorized and minimized. Preserve currency/quantity/version/operation references needed for verification without leaking unnecessary identifying information.

## External/human evidence

Partner contracts, account entitlements, non-author installation, independent contribution, merchant sign-off and actual observation windows cannot be generated by an AI worker. The worker may prepare forms, tests and analysis. If the real evidence is missing, mark the qualification blocked and leave the corresponding claim unavailable.

Human-governance work still needs regression protection: schema/checklist/claim/decision-record tests can detect deleted required information, but cannot establish legal authority or manufacture a genuine sign-off. The reviewed decision itself remains an external trust input.

## Retention and recovery

Use the existing project's retention policy. Preserve acceptance decisions, operation/test contracts, minimized source proof and artifact hashes needed for audit/reproduction. Retain fixture data under a deliberate privacy/license policy. Remove bulky generated traces and obsolete worktrees only after the required evidence has a durable, accessible home.

A cancelled/deferred goal retains a truthful terminal record and unresolved-effect references. Cleanup must never remove permanent regression tests or conceal a pending external refund/label/warehouse operation.
